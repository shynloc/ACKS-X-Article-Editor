## 1. 复审结论与基线修订

### 1.1 总体判断

原稿的产品方向成立：将可靠写作、结构转换、在线操作分开，有利于降低编辑器故障和误发布风险。但原稿尚不足以直接冻结开发，主要缺口是外部接口契约不准确、双编辑模式缺少单一真源、浏览器持久化承诺过强，以及“离线导出”和“可立即提交 payload”未区分。

本次复审只进行了附件阅读、官方文档与公开 OpenAPI 核对；未登录 X、未创建或发布文章、未验证开发者计费、未运行产品性能测试。没有现成用户访谈材料，因此原稿中的市场抱怨和需求规模应视作待验证问题，不作为已完成用户研究结论。

### 1.2 必须修正的事项

| 编号 | 级别 | 原稿问题 | 本版处理 |
|---|---|---|---|
| R01 | P0 | 自有文档直接等同 X content_state | 源文档、转换中间层、接口 DTO 分离 |
| R02 | P0 | embed_post 被当作线上类型 | 本地语义可保留，线上映射为 post |
| R03 | P0 | entities 未定义完整形状 | 明确 key/value、mutability 与引用索引 |
| R04 | P0 | depth、任意 data 可进入线上结构 | 本地保留；序列化时严格白名单 |
| R05 | P0 | 本地图尚未上传却称可提交 payload | 分离本地转换产物与最终请求 |
| R06 | P0 | 双击 HTML 与可靠跨浏览器保存混用 | 固定本地源为正式运行方式 |
| R07 | P0 | MD 与 block 双向编辑未定义冲突 | V1 源模式唯一可编辑真源 |
| R08 | P0 | confirm:true 被视为充分发布授权 | 绑定账号、草稿、内容版本的一次性授权 |
| R09 | P1 | H3、表格、代码被一概视为不支持 | 区分官方能力与产品保守策略 |
| R10 | P1 | 已保存、导出过、已建稿混成单状态 | 保存、备份、远端状态分别显示 |
| R11 | P1 | 500 字、24h、失败计费写成事实 | 改为产品阈值或待验证规则 |
| R12 | P1 | 99% 往返、零丢稿缺少测试边界 | 支持集要求 100%；明确崩溃恢复窗口 |

P0 表示不修正就会破坏数据、安全或主要流程；P1 表示会造成明显兼容性、理解或交付风险。这里只是需求复审分级，不是已实现软件缺陷报告。

### 1.3 官方契约核对摘要

**已核实事实：** X 已公布创建草稿与发布接口。直接读取的 OpenAPI 标识为 2.168；该快照包含 `header-three`，实体类型包括 `post` 与 `markdown`；range 的 key 是整数数组索引，实体本身的 key 是字符串。块属性未包含 depth，且禁止额外属性；标题仅声明最小长度，未给出 500 的最大值。[S1–S4]

**产品决策：** 不因官方 schema 存在某一类型就直接承诺线上表现。V1 默认采用保守兼容配置；未经过真实草稿验证的格式标记“结构已校验，线上未验证”。表格和代码默认出图，同时保留可恢复的原始内容。

**待验证假设：** emoji/组合字符的索引一致性、具体字号渲染、草稿编辑 URL、资格可查询性、标题与正文实际上限、每次建稿费用和错误计费规则，均不能由本次公开 schema 核对推导为已验证。

## 2. 产品目标、用户与验证假设

### 2.1 产品价值

让作者拥有一份独立于 X 的可迁移稿件，并在接触远端接口之前看清转换结果与损失。用户应能回答三个问题：我的内容保存在何处；哪些部分会被降级；当前账号究竟执行了哪一步远端操作。

成功闭环为：新建或导入文章 → 连续编辑与本地保存 → 查看结构预览和问题列表 → 导出可恢复资源包。联网建稿是后续能力，不是离线版本的成立条件。

### 2.2 主用户与任务

| 用户 | 首要任务 | 产品成功信号 |
|---|---|---|
| Markdown 创作者 | 将已有文章转成 X 兼容结构 | 不重新排版即可完成预览和备份 |
| 长文高频作者 | 稳定编辑、插图、恢复历史 | 清楚看到保存版本并成功恢复 |
| 技术作者 | 保留表格、代码与链接含义 | 降级后仍可读，原始源码可找回 |
| Agent 使用者 | 校验、导出、受控建稿 | 不接触令牌，不绕过人工授权 |

### 2.3 早期验证计划

在范围冻结前，邀请 5–8 名目标作者，使用其明确授权的脱敏稿件完成导入、修复和导出。记录任务时间、阻塞点、降级接受度及资源恢复成功情况；这是建议研究规模，不是统计代表性结论。

需要验证的假设包括：源模式是否足以覆盖首版用户；代码图片可读性是否被接受；导出包是否比“复制到官方编辑器”更有价值；作者是否愿意安装本地启动器。若多数受试者无法完成导入或不能接受出图，应先调整主流程，不增加排期和协作功能。

### 2.4 明确不做

V1 不做官方编辑器 UI 克隆、整篇手写 contenteditable、云同步、多账号管理、实时协作、移动端完整编辑、AI 改写、排期或任何 X 写请求。默认不采集用户稿件与遥测，不以 Cookie、私有 GraphQL、浏览器自动点击作为发布兜底。

## 4. 核心旅程与交互闭环

### 4.1 新建文章

用户启动应用后先看到本地存储检查结果，再新建文稿。标题为空时允许保存草稿，默认名称为“未命名文章”；标题必填仅阻断 X 就绪校验，不阻断本地写作和抢救导出。

输入 Markdown、插入图片、观察本地保存时间。点击预览时使用当前 revision 的转换结果；表格、代码旁显示“将作为图片”。完成后导出完整包，并提示核对下载文件，不将浏览器触发下载等同磁盘落盘成功。

### 4.2 导入既有 Markdown

选择 `.md`，再选择图片集合或完整资源包。导入器先在暂存区解析，展示标题处理、缺失资源、未知语法和安全问题。用户确认后生成新文稿；取消导入不修改原有文章。

只选一个 MD 文件并不授权读取同目录其他文件。缺图保留原路径、alt 与占位节点，提供“重新关联图片”，不得删除图片节点或悄悄联网下载。

### 4.3 恢复和换机器

本机崩溃后打开，恢复最后一次提交成功的本地 revision，并展示其时间。换机器时导入完整包，验证 manifest 与资源哈希；成功后才写入正式文稿库。原稿 ID 冲突时默认导入为副本，覆盖需用户选择并先保存旧版本。

### 4.4 联网建稿

V2.0 用户选择账号并查看将上传的内容；固定一份文章 revision，上传所需资源，再生成最终 X 请求并展示校验结果。用户点击“创建 X 草稿”后才提交写请求，成功后显示 article_id 与官方入口。

创建草稿不等同发布。打开官方网页后，网页端实际登录账号可能与授权账号不同，界面必须再次提醒核对。返回本地不会自动声称远端已发布或已同步。

## 5. 信息架构与状态呈现

### 5.1 页面布局

左侧为文稿库与导入入口；中间为标题、封面和源编辑区；右侧为结构预览与问题抽屉。宽度不足时使用编辑/预览标签切换，不挤压正文。底栏显示字数、block 数、当前 revision 和保存时间。

本地版本不显示可操作的发布按钮。右侧始终有转换摘要：图片化数量、降级数量、待修复数量；没有问题时明确显示零项，不空留警告框。

### 5.2 三条独立状态轴

| 维度 | 允许的状态 | 不得表达的含义 |
|---|---|---|
| 本地保存 | 未保存、正在保存、已保存到本地、保存失败 | 不代表已备份到外部文件 |
| 文件备份 | 未导出、已生成下载、已写入文件、备份落后 | 不因点击下载就宣称可恢复 |
| X 状态 | 未连接、未建稿、建稿中、已建稿、结果未知、已发布 | 不因本地保存就更新远端状态 |

每条状态绑定对应 revision 或 sourceHash。例如“已保存到本地 r42；上次导出 r39；X 草稿基于 r35”。保存失败提示需含恢复动作，不能仅用颜色或短暂 toast。

### 5.3 预览与来源定位

每次转换携带输入 revision、converterVersion 与 targetProfileVersion。旧任务晚返回时必须丢弃，不能覆盖新预览。点击警告定位源区间；输入过程中不强制移动光标，不在 IME 组合期间重写源文。

预览常驻说明“结构预览，非官方渲染”；离线嵌帖展示 ID 与占位卡，不伪装成已加载真实内容。若转换失败，保留上次成功预览并标明“预览已过期”，禁止将其用于当前文稿的就绪校验。

## 6. 编辑、导入与媒体需求

### 6.1 LIB-01 / EDT-01：稳定写作

源模式为 V1.0 唯一可编辑真源。块列表仅用于导航、诊断与定位，不实现第二份可独立修改的正文。可选用成熟的代码编辑控件，但必须通过输入法与性能基准；禁止用一个自制 contenteditable 承担整篇富文本编辑。

新建、复制、重命名、搜索、归档均在本地完成。删除进入回收站，保留 30 天为产品默认值；永久清理需要确认，不能由保存失败触发。复制文稿产生新 documentId，资源可按内容哈希复用，修改不能污染原稿。

编辑器支持撤销重做、查找、缩进、插入链接与图片引用。源文本、标题和封面变更进入文稿 revision；图片异步处理中要记录插入占位，解码完成后仍留在原位置。撤销图片插入不立刻物理删除 Blob，防止历史无法恢复。

V1.1 的有限块操作只能形成同一源文档的受控编辑事务；如果转换不可逆，操作前提示并允许取消，禁止静默重排整篇 Markdown。

### 6.2 IMP-01：导入契约

必须接受 UTF-8 Markdown，识别 BOM 与 CRLF，内部统一 LF。非法编码不猜测覆盖，提示转码并允许保存原文件。首个顶层 H1 可提取为独立标题；已有标题冲突时让用户保留原标题或替换。原始输入作为导入附件或首个快照保留，避免“提取标题”破坏追溯。

相对图片路径只在用户授权的文件集合或包根目录内解析。路径标准化后禁止绝对路径、盘符、目录穿越、符号链接及重名歧义；区分大小写，展示冲突列表。V1 使用多文件选择和 ZIP 作为跨浏览器基线；目录选择与 File System Access 仅作为增强。[S10]

未知语法不得静默丢弃。HTML 默认显示为转义文本或不支持节点；脚注、任务列表、数学公式、Obsidian 特有链接分别报告。转换失败仍允许保存源文和导出恢复包。

### 6.3 MED-01：图片与封面

V1 必须支持 PNG、JPEG、WebP 的文件选择、拖放与剪贴板文件粘贴。动画 GIF、SVG、视频和音频不属于首版承诺；保留导入错误信息并让用户转成受支持格式，不偷偷截取第一帧。

正文图片使用文档内 assetId 引用，渲染时再解析为 Blob URL。Blob URL 与绝对磁盘路径不得作为可迁移数据保存。封面独立于正文序列，可为空；16:9 仅为裁切建议，不写成官方强制要求。所有裁切和压缩产生新派生文件，原图不覆盖。

图片提供 alt 与 caption：alt 服务本地可访问性和导出，caption 可进入兼容映射；不能把二者混同或承诺 X 一定接收相同字段。上传前的派生图移除 EXIF 等隐私元数据，原始文件留在本地包中；导出时提示原图可能仍含元数据。

远程图片 URL 在 V1 不触发网络请求。用户必须手动提供文件后才能获得完整离线包；未来启用远程抓图需要独立授权、域名检查与大小限制。

## 7. 转换模型与格式规则

### 7.1 三层数据责任

第一层是 **ArticleDocument**：Markdown、标题、资源及本地编辑状态，拥有唯一真源。第二层是 **ConversionArtifact**：目标块序列、资产绑定、源区间、损失报告，是可重建派生物。第三层是 **XCreateDraftRequest**：只在资源已解析并满足目标契约后生成，禁止包含本地字段。

预览渲染第二层的目标结构。V2 最终预览渲染第三层请求并通过本地媒体映射显示图片，因此预览与提交共享同一次转换结果，不另走一个通用 Markdown 渲染器。

### 7.2 Markdown 兼容矩阵

| 源语义 | V1.0 默认目标 | 用户提示 / 限制 |
|---|---|---|
| 首个 H1 | 独立文章标题，可选提取 | 不重复插入正文标题 |
| 后续 H1 / H2 | header-two | H1 降级时记录源位置 |
| H3 / H4–H6 | header-two | H3 虽有官方枚举，保守配置暂降级 |
| 普通段落 | unstyled | 空段与硬换行策略固定 |
| 粗体、斜体、删除线 | 对应小写 style range | 以最终纯文本计算位置 |
| 行内代码 | 普通文本，保留代码字符 | 无等宽语义，明确降级 |
| 无序 / 有序列表 | 对应列表项 | 不向接口输出 depth |
| 嵌套列表 | 扁平项及可见层级前缀 | 原始层级留在源文，逐项告警 |
| 非 1 起始或续编号列表 | 保留可见原编号的普通段落 | 避免接口重置编号改变含义 |
| 引用 | blockquote | 多层引用降一层并告警 |
| 普通链接 | link entity | 仅允许 http、https |
| 本地图 | atomic + 本地资产绑定 | 上传后生成 image entity |
| 独立一行 X 帖子 URL | atomic + post | 离线不解析帖文内容 |
| 分割线 | atomic + divider | 与段落上下文一起判定 |
| GFM 表格 | PNG，一张或连续分片 | 保留原表源码 |
| 围栏代码 | PNG，一张或连续分片 | 保留语言和完整代码 |
| Mermaid | V1.0 按代码文本出图 | V1.1 才承诺图形渲染 |
| HTML、脚注等未支持语法 | 保留文本或未支持节点 | 明示损失，禁止静默删除 |

空行分段；段内单换行转换为空格，Markdown 显式硬换行转换为文本换行并进入兼容用例。任务列表转为带 `[ ]` / `[x]` 文本的列表项；反斜杠转义与链接标记在解析后计算范围。以上均为产品映射规则，不代表 X 对所有源语法的原生能力。

### 7.3 确定性和引用规则

同一源文、相同资源字节和同一转换配置，产生相同的规范化结构与诊断排序。规范化结构比较排除时间戳、随机工作 ID 和运行时 Blob URL；媒体上传 ID 不参与离线确定性比较。

本地使用稳定 nodeId；导出时按出现次序分配连续实体索引。每个实体序号 i 对应 `entities[i].key = String(i)`，range 的 key 输出整数 i。这是产品用来消除 key 歧义的规范化约束，需要真实草稿样本确认。

offset/length 按最终 block.text 的 UTF-16 code unit 计算，这是本地实现约定；官方索引在 emoji、ZWJ、组合字符上的一致性必须用黄金用例验证，未经测试不得宣称完全对齐。不得在切分时截断代理项对或视觉字素。

### 7.4 RND-01：表格与代码图片化

必须在断网条件下使用随包字体和渲染器完成。默认浅色；深色为可选参数。建议逻辑宽度 720 CSS px、2x 输出、代码正文字号 16 CSS px，作为产品初始参数；最大输出尺寸同时受设备画布能力与目标媒体配置约束，不写死成官方限制。

长代码按完整行分片；长表按完整行分片并重复表头。分片序号写入资产元数据与可见说明，插入连续 atomic，顺序与源块一致。超宽表先换行或提示调整，不缩到无法阅读；超长单行代码提供折行或人工处理，默认不裁切。

图片化会损失复制、搜索、语义结构和屏幕阅读能力。预览必须提示这一代价；包中保留原始代码/表格，允许附加文字摘要。若内容必须可复制，应允许用户改用正文文本，不强迫出图。

渲染失败保留原文并产生阻断项；缓存键至少包含内容哈希、字体集版本、渲染器版本、主题、宽度与缩放。已有派生图可直接恢复；不同浏览器重新渲染仅要求语义一致，不承诺字节或像素完全相同。

### 7.5 可选原生能力

`markdown` entity 和 H3 可在后续经过黄金用例验证后启用独立配置。原生代码/表格不得在未验证的情况下替代默认出图。每份文章固定自己的 targetProfileVersion，升级兼容配置时先生成 diff，用户接受后再改变输出。

## 8. 数据契约与版本化

### 8.1 自有文档格式

ArticleDocument 必须含 schemaVersion、documentId、revision、title、bodyMarkdown、coverAssetId、assets、createdAt、updatedAt。正文中的资源引用采用 `asset:<id>` 内部 URI；导出人类可编辑的 article.md 时重写为包内相对路径，并保存可逆映射。

Asset 至少记录 assetId、kind、mime、filename、byteLength、sha256、width、height、alt、caption、blobKey，以及派生来源与渲染参数。原图与派生图各有 ID，不复用可变字节。全部时间为 UTC ISO 8601，UI 再转成本地时间。

sourceMarkdown 与 content_state 不再同时作为权威字段。第二层转换结果单独缓存，失效时可重建；绝不从已降级的 X 输出反向覆盖原 Markdown。

### 8.2 上传和远端记录分离

UploadRecord 记录 accountId、assetSha256、mediaId、mediaCategory、uploadedAt、expiresAt、processingState。它属于某个授权账号与某份资源字节，不能跨账号复用。有效期以接口响应为准；未知有效期按不可安全复用处理。[S6]

RemoteDraftRecord 记录 documentId、sourceRevision、sourceHash、accountId、articleId、postId、requestHash、createdAt 与操作状态。修改本地文章只将“远端基于旧版本”置为真，不能假设 X 草稿被自动更新。

Token、刷新令牌、client secret、PKCE verifier 不进入文稿数据库、转换产物、资源包或普通诊断文件。客户端只读授权状态和账号摘要。

### 8.3 Schema 与迁移

自有 schema、包格式、converter 和 target profile 分别版本化。应用打开旧版文稿先保留原始快照，再迁移到新副本，通过校验后原子切换；失败继续提供原版导出。遇到未来主版本仅允许只读检查或原样导出，禁止猜测字段并覆盖保存。

X DTO 由固定 OpenAPI 快照生成/约束；新增字段必须经适配器评审。禁止“自动把所有 camelCase 转 snake_case”，也禁止原样透传未知 data 对象。附录 B 提供契约示例，不替代完整 JSON Schema 实现。

## 9. 预览、校验与就绪门禁

### 9.1 分阶段校验

| 阶段 | 检查内容 | 失败后允许的动作 |
|---|---|---|
| L0 源文与本地数据 | 文档结构、引用、哈希、资源可读性 | 编辑、恢复、抢救导出 |
| L1 目标转换 | 白名单、引用范围、降级、出图结果 | 保存和恢复包；阻断就绪结论 |
| L2 最终 X 请求 | 官方 schema、账号、媒体状态与期限、固定 revision | 修改或重新上传；禁止建稿 |
| L3 远端响应 | 状态码、data.id/post_id、错误对象、未知结果 | 核对、导出脱敏诊断；不假报成功 |

无 media_id 是 V1 的正常状态，不阻断离线文稿包；它是 V2 最终请求的阻断项。V1 UI 只能说“本地结构校验通过”，不能说“X 已接受”或“可直接发布”。纯文本请求可在本地符合官方结构，但资格与远端行为仍未验证。

### 9.2 VAL-01：最低校验项

必须检查文档版本、重复 ID、缺失 Blob、资源哈希、循环引用、危险 URL、块类型、实体类型、范围越界、负数与非整数、同类范围规范化、悬空实体、snake_case，以及目标 schema 的额外字段。

产品支持的 image/post/divider/markdown 占位 atomic 使用单空格 text、offset 0、length 1、一条实体引用。该规则只约束本产品启用的类型，不能声称所有官方 atomic 都只能用空格。链接 range 必须定位到有意义的文本区间。

报告还应列出 block 类型直方图、正文与图片顺序、封面与正文的独立引用、图片化来源、未上传资源、将发送的请求体大小、标题与正文计数及计数口径。标题 500 字符如保留，仅标为可配置软提醒；不作为未经证实的官方硬上限。

### 9.3 问题分级与用户行为

Error 阻断当前阶段的目标操作；Warning 表示有可解释损失，允许用户确认后继续；Info 提供说明。每项包含 code、severity、sourceRange、nodeId、message、suggestedAction 和 affectsStages。

“继续”只表示用户接受可降级内容，不允许越过结构错误、缺图或安全拦截。所有警告接受记录绑定 sourceHash 与配置版本，文章变化后重新计算。

## 10. 本地保存、历史与恢复

### 10.1 SAV-01：保存语义

浏览器端使用 IndexedDB 保存文稿与资源；事务提交成功才显示“已保存到本地”。成功回调并非操作系统断电下绝对不丢数据的证明，所以外部资源包仍是必要备份。[S8–S9]

建议从首次 dirty 开始最长 2 秒提交一次，输入停止后 750ms 提前提交，连续输入不能无限重置保存计时器。每次写入带 baseRevision；提交期间的新编辑留在更高的 dirty revision，旧写入完成不得把新内容标记为已保存。

IME 组合期间可保存编辑器提供的可恢复状态，但不能提交破碎字符或改写输入；至迟 compositionend 后 2 秒完成下一次提交。隐藏页面或关闭前尝试 flush，但不能依赖 beforeunload、后台计时器或后台同步完成最终保存。

### 10.2 原子性与资源一致性

资源先写暂存区并验证哈希，提交文稿时原子更新资源索引、文稿 revision 与历史记录。任何可见已保存文稿必须引用已提交资源；处理中资产只能作为明确标记的 pending 节点，不能冒充完整图像。

存储写入异常时保留内存稿、冻结垃圾回收并显示“保存失败：立即导出恢复包”。不得通过删除旧稿或清空数据库自动修复。保存正文不等待耗时的表格出图，派生物由独立任务更新。

### 10.3 历史策略

撤销栈与跨会话历史是两种机制。每次成功提交记入近期版本日志；建议保留最近 24 小时的细粒度记录，之后压缩成每 5 分钟一个检查点，保留 30 天。手动命名快照、导入前快照和迁移前快照不自动淘汰。

历史面板说明保留策略，显示 revision、时间和变更摘要，允许预览差异并“恢复为新版本”。还原不会删除当前版本。资源清理按当前稿件、回收站、保留历史和上传任务的引用集合计算；无引用派生物可延迟回收，原始资源清理需在可见策略内执行。

### 10.4 多标签、空间和异常环境

同一文稿默认一个可写会话，其他标签为只读。BroadcastChannel/Web Locks 可用于提示和锁管理，但最终保护必须依靠 IndexedDB 事务内 baseRevision 比对；锁过期或进程崩溃也不能覆盖更新版本。

检测存储可用性与空间估计，尝试请求持久化，并显示结果。持久化获准不防止用户主动清理站点数据；隐私模式或受限存储不承诺持久性。默认存储可能被浏览器回收，因此“已保存到本地”旁需提供备份入口。[S8]

## 11. 资源包、导入导出与可迁移性

### 11.1 PKG-01：标准包结构

```text
article.xas.zip
  manifest.json
  article.json
  article.md
  conversion.json
  validation.json
  assets/original/<sha256>.<ext>
  assets/derived/<sha256>.png
  optional/x-request.json
```

article.json 是恢复真源；article.md 是便于其他编辑器使用的可读副本，包含标题、正文、相对资源路径；conversion.json 是版本化的本地目标结构和资产绑定，明确不是官方请求；validation.json 保存与导出 revision 对应的报告。

只有最终请求已形成时才允许可选导出 x-request.json，并标记账号依赖和媒体过期风险。默认包不含 token、账号标识或 media_id。原稿的 content_state.json 要求由更准确的 conversion.json 承接，避免将含占位资源的文件误当作可提交 DTO。

### 11.2 Manifest 与完整性

manifest 至少记录 formatVersion、appVersion、documentId、revision、sourceHash、converterVersion、targetProfileVersion、createdAt，以及每个其他文件的 path、byteLength、sha256。manifest 不对自身做递归哈希；缺文件、重复路径、大小不符和哈希错误必须有独立错误码。

导入前验证压缩包文件数、展开体积、单文件大小、压缩比与路径安全。解包只进入暂存区；全部校验通过再创建文章。包格式未知时不覆盖现有数据。损坏包可在明确提示下导入可恢复源文为新稿，但不能显示“完整恢复”。

### 11.3 导出一致性与安全

导出固定 revision 快照；生成过程中用户可继续编辑，但导出结果和按钮文案必须注明导出的是哪一版。导出时等待该版必要派生资源完成，或选择“恢复包”明确列出未完成项；不静默漏图。

程序必须先自检 ZIP 内容与哈希，再触发下载。普通浏览器下载只能显示“已生成下载，请检查文件”；只有获得文件句柄并写入关闭成功时才显示“已写入文件”。两种方式都允许重新导入自检。[S10]

资源包默认含原文、原图与说明，可能包含隐私或未公开内容；分享前显示提醒。完整包不默认携带全部历史，仅包含选定 revision 和恢复必需数据；“包含历史”是独立选项，须提示文件增大及旧内容泄露风险。

## 12. 运行形态与工程架构建议

### 12.1 正式支持形态

**产品决策：** V1.0 正式支持“静态 Web 应用 + 本地启动器”，使用固定 loopback origin，资源、字体、依赖全部随包。首次安装完成后，在外网完全断开的条件下仍可冷启动、编辑、预览、出图与导出。启动器不得在断网首启时临时下载运行时或 npm 包。

建议固定地址为 `http://127.0.0.1:47631`，具体端口在技术设计冻结；这只是规划值，本次未启动服务。禁止端口占用时默默切换随机端口或在 localhost/127.0.0.1 间切换，因为它们可能使浏览器看见不同存储空间。[S9]

直接 `file://` 双击模式只作为可选体验模式，不纳入“可靠持久化与完整功能”验收。界面必须提示能力缺失并引导正式启动方式。浏览器对文件 origin 的处理存在差异，不能用一次成功实验覆盖所有浏览器承诺。[S11]

PWA 可在后续提供；首次安装依赖网络的路径必须与“离线包首次启动”分开描述。应用壳缓存、用户数据和 schema 迁移不得由同一个无提示更新动作处理。

### 12.2 模块与依赖方向

UI 调用 EditorService、DocumentRepository 和 Converter；Converter 输出目标中间层；PreviewRenderer 与 Validator 消费同一结果；AssetPipeline 负责图片化；PackageService 负责完整性与恢复；XAdapter 和 PublishBridge 仅在 V2 加入。

核心转换、校验和包格式应为无 UI 依赖的模块，方便单元测试和后续 MCP 复用。可采用 TypeScript、成熟 Markdown AST 解析库、JSON Schema 校验器及 Worker；具体依赖版本在技术设计和锁文件中冻结，PRD 不强绑未经实验的库版本。

Markdown 解析、图像解码、压缩和出图不得全部同步占用输入主线程。所有异步任务携带文稿 revision，并支持取消、资源释放和并发上限。Blob URL 在不用时撤销，图片按需解码，预览采用可见区渲染。

### 12.3 V2 本地桥边界

优先扩展已有本地启动器承担 token 交换与 X 请求，前端不直接持有令牌。只监听 loopback，验证 Host 与 Origin，使用会话认证和 CSRF 防护；拒绝跨站请求、DNS rebinding 场景及无授权调用。不能把“只监听本地”当作完整安全措施。

是否能注册并完成固定 loopback redirect 必须通过 X 应用配置验证；OAuth 标准建议并不等于平台接受任意回调。[S5、S12] 若回调不满足要求，应停止该模式的 V2 开关并重新评审桌面回调或服务器桥；不悄悄把私人稿件改为经过第三方中转。

## 13. 授权、媒体上传与创建草稿

### 13.1 OAuth 与账户资格

使用 OAuth 2.0 Authorization Code + PKCE S256、随机 state 和精确匹配 redirect URI。初始权限集为 tweet.read、tweet.write、users.read；媒体上传增加 media.write；需要持续登录时才申请 offline.access，并在用户开启时说明用途。[S1、S5]

开发者控制台 API 权限与额度、账号 Articles 资格、OAuth scope 是三个独立条件。官方帮助页列有 Premium、Premium+ 及相应组织订阅，但用户对象中的 verified 等字段不能直接当作 Articles 发布能力证明。[S7]

capability 状态分 eligible、ineligible、unknown。没有可靠资格查询时显示“资格未确认”，引导用户人工检查；不得每次校验就调用建稿接口探测。用户知悉后可以授权一次实际建稿尝试，明确的资格错误再阻断后续操作。

V2.0 首版只维护一个活动账号；切换账号需要显式操作，并使原上传映射和未完成授权失效。始终显示 handle 和用户标识摘要，不能仅用头像判断身份。

令牌默认只在桥进程内存中使用；用户选择保持登录时，使用系统凭证存储（如 macOS Keychain 或 Windows Credential Manager），不可用则回退到会话登录，禁止明文落盘。公有客户端不嵌入共享 client secret。刷新令牌轮换需要原子替换并防止并发刷新；退出时删除本地凭证，并在有网络和官方支持时执行撤销。退出登录不删除本地稿件。

### 13.2 媒体任务

用户确认联网操作后才上传封面与正文派生图。按账号与字节哈希去重，默认上传并发 2；这是产品参数。解析返回 media ID、处理状态及有效期；如需状态轮询，按返回建议等待，不把“收到 ID”当作处理成功。[S6]

上传完成后不能根据列表排序重新排列正文；通过资产绑定表写回对应节点。单图失败时其他已开始任务可完成，但建稿保持阻断。取消不会删除本地内容，也不承诺已上传远端媒体自动撤销。

默认在提交前保留 5 分钟有效期余量；不足时重新上传。该值为产品保守缓冲，不是官方 24 小时规则。没有有效期信息时记录未知，并在当前会话完成提交或重新确认，不能永久缓存。

### 13.3 最终请求与草稿结果

所有媒体映射完成后生成不可变请求，计算 requestHash，执行 L2 校验，再展示摘要：目标账号、文章标题、固定 revision、正文块数、图片数量、降级项和可能的计费提示。正文在此期间变化则使确认失效，必须重新生成请求。

收到 201 且有效 data.id 才记录“已创建 X 草稿”；同时检查 errors，不能只看 HTTP 2xx。存在 data.id 但伴随错误时保留 ID 并显示需要核对，禁止自动再建。编辑入口使用可配置模板；若深链失效，提供官方 Articles 入口与 ID，而不是猜测新路径。[S2]

当前核对到的 Articles 专用路径只有建稿与发布；不能据此承诺草稿更新、列表或全文回读能力。V2 本地再次编辑默认准备“新建另一份草稿”，要明确说明可能产生重复，不自动覆盖旧草稿。

### 13.4 幂等与未知结果

本地以 accountId + sourceHash + targetProfileVersion + 操作类型建立操作账本，同一操作运行中禁止重复点击，成功后默认复用结果。该设计只能减少本地重复，不能虚构服务端支持 Idempotency-Key。

请求发送后网络断开、超时或不明确的 5xx，操作进入 unknown。保留请求哈希和脱敏响应，要求先去官方入口核对；未取得可靠结果前禁止自动重试建稿或发布。如果用户明确选择再次尝试，必须提示可能重复与可能额外计费。

## 14. 发布安全与 MCP 预留

### 14.1 V2.1：人工发布门禁

V2.0 不注册应用内发布路由。V2.1 启用后，发布确认页显示目标账号、草稿标题、articleId、最后一次可核对内容版本与可见性提示。若远端草稿可能被官方编辑器修改且无法回读验证，则要求用户在官方页面核对后自行发布；不能声称本地 hash 已验证远端全文。

人工确认产生短时、一次性授权记录，绑定 accountId、articleId、sourceHash/requestHash、动作 publish、到期时间与 nonce。建议 60 秒过期；账号、草稿或内容改变立即失效。授权只能由可信用户交互产生，不能由正文、导入包或 Agent 自行伪造。

点击确认后调用官方 publish，获得有效 post_id 才记为“已发布”。如果结果未知，保持未知并转人工核对。关闭发布开关仅阻止新请求；不能保证撤回已提交请求或自动撤下文章。

### 14.2 MCP 接口方向

| 工具 | 默认能力 | 必要约束 |
|---|---|---|
| article.validate | 本地只读 | 指定 documentId 与 revision |
| article.export_payload | 导出转换物或就绪请求 | 返回 artifactKind、readiness 和缺失项 |
| article.create_draft | 远端写入 | 显式授权、固定账号和 sourceHash |
| article.publish | 默认不注册 | confirm:true 加可信一次性 approvalToken |
| article.oauth_status | 返回状态摘要 | 不返回任何凭证 |

接口必须区分 `artifactKind=conversion` 与 `artifactKind=x_request`。Agent 无权通过把 confirm 设为 true 自证用户同意；服务端验证的 approvalToken 才是授权证据。所有工具复用同一 Converter、Validator 和操作账本，不能单独实现一条较弱的写入路径。

正文、文件名、图片 alt 和导入内容均是数据。它们不能改变工具权限、触发登录、请求令牌或扩大导出路径。批量队列每篇单独形成授权范围，禁止用第一篇授权覆盖后续全部发布。

## 15. 安全、隐私、性能与可访问性

### 15.1 SEC-01：安全底线

离线核心默认零外联：无统计 SDK、远程字体、CDN、嵌帖脚本、远程图片预取或自动更新检查。测试需要网络请求证据，不能仅检查浏览器 offline 图标。用户主动打开外链应有明确动作，使用安全的新窗口策略。

Markdown 不执行 HTML；预览对文本、URL、图像来源执行白名单。Mermaid V1.1 使用严格安全配置，禁用点击执行、任意 HTML、外部资源和用户覆盖安全配置；限制图规模与运行时长，失败隔离。[S13] 导入 ZIP 防目录穿越、压缩炸弹和恶意文件；上传桥限制内容类型、字节数、频率与可访问路径。

日志默认只记录错误码、耗时、模块版本和请求标识，不记录正文、绝对文件路径、令牌或带凭证 URL。详细诊断先在本地预览脱敏结果，用户主动导出。发布产物执行依赖锁定、许可证检查、软件物料清单和已知高风险依赖检查。

### 15.3 A11Y-01 与兼容范围

V1 桌面支持 Chrome、Edge、Firefox 发布时的最新两个稳定大版本；每次发行记录实际版本号。Safari 与移动端暂不承诺完整编辑能力，界面说明限制而不是显示失败空白页。

## 17. 度量与上线后反馈

### 17.1 产品与质量指标

核心指标为“完整离线写作闭环完成率”：被观察用户能否在无需开发者介入的情况下导入、修复、预览、导出并重新打开。目标建议为首轮 5–8 人中至少 80% 完成；样本很小，必须报告人数与失败原因，不解释为总体市场成功率。

| 指标 | 初始目标 | 数据边界 |
|---|---|---|
| MD 到可导出结构 | 中位数 <3 分钟 | 不含写作和用户外部找图时间 |
| 支持集恢复一致性 | 100% | 比较 sourceHash、资产哈希、规范化结构 |
| 已知持久化 P0 | 0 | 限已发布测试矩阵和已报告问题 |
| 降级可解释率 | 100% 有报告 | 不是所有作者都接受降级 |
| V2 建稿成功率 | ≥95% 为后续目标 | 分母为用户确认后的尝试，未知也计失败 |
| 未授权发布 | 0 | 自动化负例与操作审计共同证明 |

建稿同时报告全量成功率，以及排除可明确分类的网络/资格/额度问题后的诊断指标，不能只公布排除失败后的数字。样本不足 100 次时报告分子、分母和错误分类，不据此承诺稳定成功率。

### 17.2 隐私友好的反馈

V1 指标通过测试和自愿研究收集，不启用后台上报。用户可以主动导出只含版本、错误码、耗时和匿名统计的诊断包；需附正文时必须单独选择并看到将发送的范围。反馈流程不要求作者交出私密原稿。

## 19. 风险、回滚与变更治理

### 19.1 主要风险

最大风险不是样式不像 X，而是让用户以为已保存、已完整导出或已完成远端操作。应优先保证状态真实性、可追溯 revision 和恢复入口。其次是 schema 与后端表现漂移：固定 target profile，保留最近可用适配器，新增能力采用显式开关。

外部 API 不可用时关闭在线操作并保留离线核心；字体或图片渲染异常时保留源文与已完成资源；数据库迁移失败时保留旧版，不以清库重建规避。未知语法不能自动“降成空段”，更不能默默消失。

### 19.2 回滚要求

应用升级前创建可恢复备份；数据库迁移必须可回到原始数据副本。若新数据格式不能被旧程序读取，回滚流程要恢复备份而不是让旧程序直接打开新库。离线安装包保留前一稳定版本和校验值。

桥模块可独立禁用。禁用不改变已经创建的 X 草稿或已发布内容；外部副作用不能靠回滚本地代码撤销。对需要人工撤稿或检查重复草稿的情况，给出清楚的人工操作提示，不自动删除远端内容。

### 19.3 需求冻结与交付责任

产品负责人确认范围和降级接受度；技术负责人确认运行容器、schema 与迁移；测试负责人确认数据恢复和异常路径证据；安全/桥负责人确认令牌、回调和发布门禁。角色可以由同一人承担，但验收记录不能省略。

任何改变默认数据外流、引入远端服务、放宽发布授权、替换本地真源或改变包恢复契约的需求，必须作为显式变更评审。正式文档完成不等于这些变更已经获批。

## 附录 A. 核心状态与不变量

### A.1 保存与导出

保存状态：clean → dirty → saving → clean；任一步写入失败进入 error。saving 时出现新输入保持较新的 dirty revision，旧提交完成只能确认其自己的 revision。导出状态独立为 idle → generating → download_triggered / file_written / failed。

本地不变量：可见已保存文稿的资源引用可解析；一个 revision 对应一份固定内容；回滚创建新 revision；包生成自固定快照；任何失败不删除未提交内存稿；恢复与备份状态不依赖 X 登录态。

### A.2 草稿与发布

建稿状态：idle → preflight → uploading → ready_for_confirmation → submitting → succeeded / failed / unknown。failed 只表示已知失败；无法判断服务器是否执行的情况必须进入 unknown。

远端不变量：账号/源文变化使确认失效；媒体记录不跨账号；同一操作不并发提交；未知写入不自动重试；响应未提供有效远端 ID 不标成功；发布需要独立可信授权；打开官方编辑器不等于已同步或已发布。
